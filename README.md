# Задача
Необходимо обучить модель для классификации объявлений по категориям товаров и услуг

# Датасет и метод решения
Весь процесс решения описан в ноутбуке ```farpost.ipynb```, там же описан датасет -- набор из 1.5 млн объявлений с авито, включающий картинки.

В качестве метода решения был выбран transfer learning по следующим причинам:

- Для него нужно мало данных и времени
- Дает хороший результат на общих задачах
- Требует обучения только одной небольшой модели
- Позволяет работать с мультимодальными данными без обучения своего энкодера

Недостатков у этого подхода немного: он ломается на уникальных и узкоспециализированных задачах (не наш случай) и эмбеддинги считаются достаточно медленно

Этот метод является самым простым и эффективным методом для решения данной задачи, так что это очевидный выбор

В качестве альтернатив можно взять так же обучение собственной пары моделей типа BERT для текста или сверточной модели для картинок, но так вообще никто не делает, если задача не супер уникальная, нужно слишком много вычислений, данных, времени и нервов, требования к качеству датасета также очень высокие

Еще можно сделать проще и использовать мешок слов + любая модель классификации типа леса, градиентного бустинга или байеса. Скорее всего, в этом случае этот подход будет работать неплохо, так как классификация в данной задаче зачастую привязана к лексике отдельных слов, значит мешок слов скорее всего сможет захватить эти зависимости (при условии лемматизации, конечно)

# Результат
Итоги также приведены в ноутбуке, но если кратко, то получилось добиться точности 90% на валидации для обеих голов категорий и подкатегорий

# Возможные сложности
В ТЗ приведены примеры сложностей в задаче:

- Пересечение в категориях можно легко решить присвоением более одной категории объявлению, например, по накоплению пороговой вероятности top-k классов, выбранных моделью, либо переходом к multilabel задаче классификации и выставлению категорий по пороговому значению вероятности (если категории сильно пересекаются)
- Задачу вложенности я частично уже решил, здесь самый простой вариант -- обучить несколько голов на каждый уровень вложенности, в идеале же нужно при выборе подкатегории маскировать все подкатегории внутри не выбранных категорий, чтобы не было противоречий
- На самом деле достаточно тяжело отследить ошибки юзеров, я могу придумать разве что вариант, когда юзер перепутал картинку или написал не тот текст, тогда возможен случай, когда модель уверенно выбирает несочетающиеся категории в разных головах, здесь можно проверять такие случаи вручную с помощью кожаных мешков ой то есть модераторов
- Если вдруг мы захотим добавить новую категорию, что не редкость, но модель придется переобучать, что в данном случае не тяжело, однако если категории добавляются часто, то появляется проблема. Её можно решить, если убрать голову и посчитать эмбеддинги каждой категории, и сравнивать эмбеддинги объявлений по косинусному расстоянию с эмбеддингами всех категорий, выбирая ближайшие. Таким образом можно хоть каждый день добавлять категории, главное считать эмбеддинги. Я думаю, что точность в этом случае уменьшится, но это приемлемая жертва в данном случае

# Потенциальные улучшения
Здесь можно много чего придумать, например:

- Поиграться с обучением, датасетом и его чисткой и довести точность до 95%, я думаю, это будет несложно (учитывая, что добавления весов для балансировки классов увеличило точность определения подкатегорий на 5%)
- Добавить больше уровней вложенности и сделать дерево категорий несбалансированным
- Можно поэкспериментировать с использованием других фичей объявлений, вроде данных о юзере -- разные юзеры работают в разных областях, как, например, магазин электроники и бытовой техники будет выкладывать объявления только в этих категориях
